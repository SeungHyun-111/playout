# 통합 우선순위

## 현재 방식: 기간별 설정 (schemaVersion=5)

`settings/exceptionPriority`에 `{schemaVersion:5,groups:[{id,name,startDate,endDate,stages}]}`로 저장한다.
기간마다 시작일·종료일을 한 번 입력하고, 기본 규칙과 개별 항목을 함께 정렬한다.
단계별 날짜 입력은 없으며 과거 단계 날짜 값도 이 방식에서는 무시한다.
기간 밖은 기존 기본 우선순위와 조건을 따른다. 기간이 겹치면 위쪽 첫 유효 기간을 사용한다.
아래 schemaVersion=4 설명은 이전 방식의 호환 동작이다.

`settings/exceptionPriority`의 schemaVersion=4는 기간 그룹 없이 stages 순서로 우선순위를 저장한다.

- 기본 규칙: `{id, targetType:"base", priorityKey}`
- 등록 항목: `{id, targetType:"promotion"|"plannedPgm", targetId, startDate, endDate}`
- 시작·종료일은 항목별이며 공란은 추가 제한 없음이다. 원본 등록 항목의 유효기간·방송 일치 조건은 유지한다.
- 목록의 0단계가 최우선이다. 기본 규칙과 특정 항목을 함께 이동할 수 있다.
- 예: 카드배너 제외 → 특수요청 → 메가진(장기간) → 오픈런(3일) → 기획PGM 전체 → 프로모션 전체.
- 기본 규칙의 상세 조건은 기존 운영설정을 참조한다. 특정 항목이 적용되지 않으면 그 단계를 건너뛴다.
- 빈 소재는 하위 단계로 이어진다. 특수요청은 기존 동작대로 빈 슬롯도 명시적으로 비운다.
- 카드배너 제외 역시 목록의 위치에 따른다. 그보다 높은 소재 규칙은 배너1을 적용할 수 있고 낮은 규칙은 제외를 이길 수 없다.
- 기본 6개 규칙은 삭제하지 않고 이동·기간 수정만 가능하다. 누락된 규칙은 마지막에 보완한다.
- schemaVersion=1/2 및 기존 priorityExceptions는 호환 조회한다. 신규 화면에서 수정하거나 현재 순서 적용을 누르면 schemaVersion=4로 전환한다.
- 4번 방식에서는 기존 기본 화면의 드래그를 비활성화한다. 적용 순서는 통합 목록 한 곳에서 관리한다.

UI의 단계 번호는 배열 위치에서 계산한다. 날짜가 지나도 번호를 다시 매기지 않으며 해당 단계의 적용만 건너뛴다.
